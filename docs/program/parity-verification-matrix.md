# CoinLine configuration and terminal parity matrix

This is the current acceptance summary for the management console and terminal configuration catalogue. A message type (MT) identifies a record on the management link. A byte count includes the message type where a complete record length is known.

An editor, valid encoding, a terminal acknowledgement and observed device behavior are four different milestones. An acknowledged record does not prove its feature works. A synthetic TCP fixture is not an emulated terminal, and an emulated terminal is not a physical terminal. Unknown layouts remain available for controlled binary import rather than being treated as verified typed fields.

## Acceptance rule for future edits

For each applicable profile, retain a known-good payload, save it unchanged, compare its digest, edit one documented field, confirm only the intended bytes or bits change, deliver the correct selected record, and observe the application acknowledgement. Finally, demonstrate the corresponding device behavior and repeat where appropriate on physical equipment. If a step cannot be performed, record it as pending rather than inferring a pass from a different test.
