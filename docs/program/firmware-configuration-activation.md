# Staged configuration activation

Firmware jobs includes a separate staged configuration activation workflow. It maintains the current registered firmware and published table assignment until the running controller reports an independently expected target version. It does not initiate code delivery or establish code compatibility.

1. Prepare a separate published target configuration explicitly associated with the intended registered firmware. Review the target's required table families, record lengths, management identity and site-specific configuration. The phone must have an existing published source assignment and a matched live MT60 report.
2. Create the dedicated enabled MT94 schedule through the existing firmware scheduler. In **Staged configuration activation**, select the phone, published target set and exact schedule. Enter the expected controller software label from the intended running version. The requested ROM is read from the scheduled record; the download application revision is displayed separately and is not interpreted as the observed software version.
3. Preview and stage the plan as an administrator. The plan retains the source assignment revision, both configuration snapshots, exact scheduled record and source controller report. Staging changes neither the phone nor the code schedule.
4. Allow the normal scheduled MT94 delivery and genuine device upgrade workflow. The Manager waits for the matched terminal MT14/94 and a later live MT60 report from a separate NCC connection opened after acknowledgement. Diagnostic imports, earlier reports, a planned schedule or a completed simulation cannot establish the target version. After schedule delivery, the old assignment is held unless the requesting connection itself establishes the source version; a reported different version keeps the hold while the transition is pending.
5. After the target report and current connection close, refresh the transition status and activate the reviewed target. The registered firmware, assignment, previous assignment and original queued full target download are updated atomically in PostgreSQL. Open the target download and inspect individual acknowledgements. Activation in the Manager is not a terminal service confirmation.

The activation review rechecks current configuration snapshots and outstanding management work. It refuses stale source or target data, an altered schedule, mismatched version evidence or concurrent changes. Cancellation of an undispatched plan does not cancel the independent code schedule; cancel that schedule separately when appropriate. Once the schedule has started or another running version was observed, the plan is retained for recovery instead of silently restoring the old configuration.

This workflow does not yet automate activation during the first post-upgrade contact, nor establish a firmware rollback or native code-server transfer. The prior configuration is retained for reviewed recovery, but it must not be downloaded against a different installed version. Qualify actual code transfer, compatible image pair, reboot, complete target table download and device service in an isolated bench before use on operational terminals.
