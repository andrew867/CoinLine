# Editor catalogue byte-preservation regression

`EditorCataloguePreservationTests` takes every registered native editor layout from `NativeTableLayouts.ReferenceLayouts()`, including each explicit profile of a shared record length. It covers all listed record numbers, not just a representative member of a segmented family. Text advertising (MT29) is tested separately because it uses a dedicated codec.

For each layout the regression reads three deterministic synthetic records, including retained unknown values and every graphical screen kind. It verifies that every field fits its record, declared credential fields return no readable value, and submitting all readable values or no changes preserves the exact original bytes. A separate test makes one explicit non-credential field change in each layout, using an existing draft template where available, and verifies the unchanged prefix, unchanged suffix, unchanged bits outside the selected mask, reopened field value and repeated-save stability. Text advertising includes retained slots after the sequence end marker and an independent spare-byte edit.

The initial run passed 191 test cases: 94 unchanged-save comparisons, 94 single-field layout checks and three MT29 vectors. These are codec tests, not verified operational records or new authoring defaults. An unrecognized layout is not added to the supported catalogue merely because its length matches; import-only portions remain import-only. Existing per-profile PostgreSQL, terminal acknowledgement and device behavior evidence must still be tracked separately in the [parity verification matrix](parity-verification-matrix.md).
