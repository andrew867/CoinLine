# Demo configuration starter data

CoinLine can load a locally supplied demo configuration bundle when initializing a lab installation. The data is provided independently of the application repository; the importer and synthetic tests are shipped with CoinLine, not the original binary bundle.

Set `Platform__Seed__EnableDemoData=true` and `Platform__Seed__DemoConfigurationBundlePath` to the expanded bundle directory containing `manifest.json`. For Docker, set `COINLINE_DEMO_BUNDLE` to the local expanded directory and use the ordinary Compose configuration with the optional `docker/docker-compose.demo-seeds.yml` overlay. The data directory is mounted read-only; the importer writes verified table records to PostgreSQL. Leave the overlay off for installations that should not include demonstration data.

The manifest must identify the unframed message type, group, relative filename, complete record and body lengths, and SHA-256 digest. The initial format contains the 12 earlier and 27 later records; the expanded format below adds explicit advertising and ordinary routing selections. Each record starts with its type byte; its packed record length is checked against the matching registered table profile. Review-only metadata is not imported as a table. A missing, incompatible or digest-mismatched record refuses the bundle rather than silently importing a partial starter.

With the initial format, the result is two named starter drafts, **Demo starter, MTR 1.9** and **Demo starter, MTR 2.x**, not a mixed terminal configuration. On a new installation they appear as default starter drafts. When exactly one registered firmware version has the corresponding table profile, the starter targets that version; otherwise the operator selects an actual matching firmware. Restarting never overwrites an existing named starter's record data or changes an assigned configuration.

The initially supplied earlier bundle contains an intentionally blank MT29. A successful hash check confirms the exact record was imported, not that it contains advertisements. Inspect the **Visible idle text messages (MT29)** count and the MT26 on-hook enable flag before copying a demo record into a working configuration. An enabled rotation with message 1 marked End sequence has no idle text advertisements. Retain the phone's working MT29 if the supplied demo record has no visible messages. The separately available graphical starter adds the bundled twenty image frames to a suitable graphical draft; neither the earlier blank text record nor the standard later starter contains MT131, MT132 or MT133.

These datasets contain examples of earlier and later tariffs, coin validation, display, schedules and other settings. The earlier tariff row 0 represents a 25-cent whole-call local charge; the next row is five cents per minute. The record containing the initial operating mode may be unset. Complete the actual terminal identity, management access, route references, operating mode, coin/card acceptance, carrier and missing required records before publishing. Reconstructed rates or numbering examples are not current geographic or commercial data. Protected account data and operational destinations must be configured separately. No starter is automatically published, assigned, or downloaded; verify terminal acknowledgement and actual behavior when preparing a site-specific copy.

## Expanded demonstration bundle

An expanded manifest retains 70 validated record files, including identical alias payloads, and explicitly selects the populated standard text advertisements and original ordinary screening defaults. The importer checks that both selected text rotations contain visible idle messages, that the graphical set contains twenty bitmap and four mixed screens, and that the standard free screening rules use the correct unrated tariff reference. A structurally valid but blank default advertising record is refused.

| Default starter | Records | Target profile |
| --- | ---: | --- |
| Demo starter, MTR 1.9 | 13 | Earlier 200-entry Multi-pay |
| Demo starter, MTR 2.x | 32 | Later 180-entry Multi-pay |
| Demo starter, MTR 2.x graphical | 35 | Later graphical 180-entry Multi-pay |

The graphical starter uses the complete three graphical records together, retaining their original screen ordering and transitions. Alternate text and screening variants, the pristine blank text record, extra language records, singly compressed exchange references, sequential rate comparison and alternate graphical/key navigation are separate non-default reference drafts. Records that are absent from a verified target catalogue are not silently included in its default set. All validated binary payload digests remain represented in the imported drafts.

Both ordinary numbering-plan overlays are structurally checked. The offsets outside the existing site-specific segment may be applied to an independently configured 353-byte MT62 for the matching profile; the bytes at offsets 19 through 31 must remain untouched. An overlay is not a full record, and startup does not invent management access, payment or other site-specific settings. Complete these in the normal configuration workflow before assigning a copy to a phone. The earlier local exchange examples also require site-specific adaptation. Alternate variants and protected record families must be reviewed for the actual device, rather than indiscriminately merged into a complete set.

When an expanded bundle replaces an untouched initial default draft, CoinLine retains the initial export as a non-default reference and creates the new default under the normal name. If the initial draft was edited or published, it is kept intact and the expanded copy is created separately. Repeating startup does not overwrite either draft, assign records or queue a download.
