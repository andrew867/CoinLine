# Table management

Register installed builds under **Firmware versions**, then select the installed build on each phone. Select the same **Target firmware** on a table-set draft if it is intended for that build. A set with a target can be assigned only to phones registered with that version. The draft's firmware review reports record lengths that conflict with a verified layout.

The firmware registry distinguishes compiled catalogue lengths from records acknowledged by an emulated terminal. The later MTR 2.x Multi-pay profile describes the 180-entry screening and sixteen-segment double-compressed image. The separate type 40 graphical Multi-pay profile is based on the MTR 2.12 controller and adds MT131, MT132 and MT133. A record absent from a complete compiled catalogue cannot be published for that target. A phone registered with a known profile also checks its selected records at pickup.

Additional observed profiles cover MSR 1.7-family Multi-pay, Card-only, Desk and Coin Basic, MTR 1.9 Desk, MTR 1.13 Multi-pay/TTY, MTR 1.20 Multi-pay and Coin Basic, and early MTR 2.0 and MTR 2.11-class Multi-pay. They record the exact acknowledged subset, not a complete image catalogue. The early MTR 2.0 evidence includes record acknowledgements but an unsuccessful cold INSTALL. Unknown record types are not ruled out, and known lengths are enforced at publication and pickup. When an observed target has more than one candidate native layout for a record, explicitly choose the layout whose field meanings have been established for that build. The editor will not automatically select one based only on the shared length. A unique wire-length candidate and an acknowledged record still require individual field and device verification.

1. Open **Table sets** and select the set for the target firmware. Make a named draft copy of a published set to retain its existing records.
2. Open **Terminal configuration**. Under **Text and display**, choose **Text advertising** to edit the 20 message slots. **Edit as text block** changes the text while keeping each slot's duration and display mode. Mark the first unused slot in a rotation **End sequence**. For a timed blank, leave the text empty, set a duration, and clear **End sequence**. The editor saves a 481-byte MT29 record.
3. Select another record to open its native fields. **Terminal features and call setup** includes Multi-pay, Card only and Coin only. **Cards, coin and carriers** includes coin slots, magnetic-card ranges and carrier acceptance. Call screening and tariff records have their own editors. Use the entry selector and search on lists with many records.
4. Start coin validation, optional quick-access, service restriction, promotion or discount records from an inactive template on a draft. Import a complete record built for the target firmware when a template is unavailable. For records of the same size, the editor uses a verified target layout when one is registered. Otherwise, select the matching layout before editing. Published records are read-only.
5. Publish the draft. In **Assign this set**, choose a phone, group, region, location or customer and preview which phones will be updated. Use **Within region** to narrow a group. Updates apply to the current eligible phones. A set that sends a terminal access record is eligible for phones with that wire ID.
6. Check **Downloads** after the terminal requests a transfer. The batch shows each table's acknowledgment and completion status.

To classify a build already in service, open **Firmware versions** and choose **Review profile change** on that build. Select the verified profile that matches the installed firmware, then **Preview impact**. Review the counts for the affected phones, sets, queued and scheduled downloads, and active sessions. Resolve blocking findings first; draft-only incompatibilities are advisory. Apply the reviewed profile or cancel. A changed configuration requires a fresh preview. This retains the existing registry ID, phone assignments, table bytes and prepared selections. Clearing the profile removes its known-length checks; it does not make an incompatible record valid.

For one phone, open **Downloads**, select the phone and a published set, then choose **Entire set** or **Selected records**. **Create batch** prepares the exact versions and shows a link to the pending batch. The terminal's next eligible ordinary call changes that same batch to running and records each acknowledgement under its timeline. Any necessary records come along with the selection. The phone's normal assignment stays in effect for later requests. A cold installation or memory recovery takes priority and receives the full assignment. Once completed, it cancels older partial work only when the exact requested versions were acknowledged during that installation. Different versions and future scheduled work remain queued. The cancelled partial history identifies the completed full installation rather than claiming a separate transfer.

On an interrupted download, the timeline distinguishes a missing link acknowledgement for a fragment from a missing table acknowledgement (MT14) after all fragments were accepted. **Not sent** means the transfer stopped before that record began; it does not mean the terminal rejected it. Earlier successfully acknowledged tables remain marked as such. The batch-level error identifies the interruption, including a missing start or end acknowledgement. A retry creates a separate batch and does not turn an unacknowledged record into a successful one.

Known firmware incompatibility is checked before changing an assignment, scheduling or queuing a download. A phone's assignment choices and fleet preview identify the conflicting record and, for a size mismatch, both lengths. If only one compatible record is needed, choose **Selected records** rather than assigning or sending an incompatible full set. Required companion records must also be compatible. The phone's next call repeats the check against its registered profile before bytes are sent. A missing or incomplete profile does not certify compatibility with unverified records.

In a draft table set, open **Copy saved records** to reuse selected records from another saved set. Select a source, check the records you need, and choose **Review copy**. The review lists additions, replacements and any required records from the source. Confirm the copy, then open the relevant editor to review the draft before publishing and assigning it. If either set changes, use **Reload sets** and review again.

To update only selected records in the full assignments, open their published source set. Under **Assign this set**, choose **Update selected records** and select a phone, group, region, location or customer. Choose **Use source record** or **Remove from assignment** for the records to change. The preview shows each phone's current set, actions and any compatibility or open-download issue. Phones on different sets can receive different resulting sets, with their individual records carried forward. Confirm the review to update the assignments for the next explicit table request. To undo an update for one phone, use its assignment rollback. Removing a record from an assignment can leave the previously installed record on the phone.

For shared manager access settings, select **Use source record** for MT21, then explicitly choose **Use each phone's registered wire ID in MT21**. By default the original identity check remains in force. This option accepts the verified 18-byte and 48-byte profiles; a known registered firmware must match the selected length. The preview reports unavailable or nondecimal identities, incompatible profiles, and the separate resulting set for each eligible phone. The identity is taken from the registered phone, not entered as a replacement in the rollout. All other source bytes, including manager numbers and any applicable ADSI identifiers, are copied unchanged, so review them for the intended phones. Existing records outside the selected update stay intact. Confirmation changes the desired assignment only; open each resulting set using its phone-labeled link to prepare a selected MT21 download. A repeated unchanged update does not create another set. A paused personalized rollout requires a new review or skip if the phone's registered wire ID changes.

Select **Pause rollout at the first blocked phone** to process the reviewed phones in terminal ID order. **Begin with terminal ID** optionally starts at a specified phone in the selected scope. The review shows how many assignments will change before the rollout pauses. **Record rollouts** shows the blocked phone and its issue after you reopen the source set. Correct the issue and choose **Retry phone**, or choose **Skip phone** to continue from the next phone. **Stop rollout** ends the run with completed changes in place.

For a scheduled delivery of specific records, choose **Schedule selected records** and select the records from the published set. The preview lists the records that will go over the wire, including required records referenced by the set. Pick **Prepare now for the next call-in** or a future preparation time. Once the host packs the records, **Scheduled downloads** shows **Ready for pickup** and links to the prepared batch. The next matched routine call-in or callback delivers that batch. The history shows preparation, pickup, and completion separately and retains the previous attempt when a call fails. A phone's existing full assignment continues to supply future explicit table requests.

To schedule by **Configuration ID**, name the record in **Versions in this set** while the set is a draft. Use the same ID on revisions of the same configuration. Publish the set before scheduling. In **Schedule selected records**, choose **Configuration ID** and select the named record. The preview matches phones whose current full assignment uses that ID for the same message type. A phone can match even when its assigned set and record bytes differ from the source. The scheduled delivery uses the source record and its required records.

Give phone groups their **Group ID** under **Phone groups**. Use three to six letters or digits. In **Assign this set**, choose **Group ID pattern** to include phones in any matching group. The pattern starts with three literal characters. Use `?` for one character or end with `*` for the remaining positions. For example, `ABC1?0` matches six-character IDs with one variable position, and `ABC*` matches IDs starting with `ABC`. Use **Within region** to narrow the results. The preview shows each phone once across its memberships.

Record the operator-assigned **Time area** in **Terminal inventory**. Use a two-character code such as `00`, `ES` or `+1`. Use `00` for phones in the manager's own time area when that is your site's convention. To schedule MT35, choose **Schedule selected records**, then **Time area**. To schedule MT94, use **Time area** in **Schedule firmware parameters**. A time area is a selection code. Set the terminal's clock adjustment and delivery times separately.

In **Terminal display preview**, inspect a single message or play a complete sequence. MT26 controls which contexts are available. When quick-access or call-established advertising is enabled, slots 1 through 10 run on hook and slots 11 through 20 run in the enabled off-hook contexts. The preview supports static, flash, alternating and scrolling modes. Select **MTR 1.9 terminal timing** to use the set's MT30 scroll interval when present, or **Maximizer preview timing** to adjust playback intervals in the browser.

Use **Display character palette** for French and Spanish accents and other supported Western display glyphs. Select a message and insert a character at its cursor, or type and paste supported text into either the individual field or the text block. The width is 20 display cells after Unicode normalization. The palette does not set a terminal language; MT29 contains a single text sequence, and accented characters require compatible display hardware. Japanese and other model-specific glyphs have not been validated for authoring.

Imported text containing unmapped cells is identified in the editor. Its exact bytes survive timing, mode and spare-field changes; replace the unmapped text explicitly when you want to rewrite the message. In each message's **Spare fields**, you can inspect and explicitly change the unnamed attribute bits 4, 5 and 7 and the reserved byte (0 to 255). Their behavior is not assigned in the verified text-advertising profiles. Leave them unchanged unless the intended target firmware documents their use.

Under **Terminal features and call setup**, MT26 includes incoming calls, rating and routing, languages, data port, and reporting. MT30 separates prompt timing, call timing, operator and carrier access, and data-port timing. When **Firmware profile** is offered for MT26 or MT31, select the layout that matches the installed build. The same record length can store different fields. In **Installation and service**, enter a replacement craft access code or desk terminal key card number only when it needs to change. A blank field retains the stored value.

In **User interface parameters** (MT30), the prompt and display timing panel shows the current packed ticks and their equivalent seconds. To change one of these timers, select the field, enter an exact duration from 0 to 327.67 seconds with at most two decimal places, and choose **Stage exact ticks**. For example, 0.25 seconds is 25 ticks. The original typed tick fields remain available. The staged change is included when you save the draft, even if you switch to another section first. A duration readout is a unit conversion, not a measurement of the terminal's actual timing. Verify the new setting on matching firmware before fleet deployment.

MT26's **Carrier payment rerouting** section selects whether the terminal may consider alternate carrier routing for coins, credit cards, stored-value cards and calling cards when the selected carrier does not accept that payment method. It does not grant card acceptance or replace host authorization. Review the actual destination carrier and applicable screening references before publishing. The four unassigned high bits are separately editable under **Spare fields**. The older MT26 Call setup section also exposes five unused bytes which are assigned to different functions in later firmware.

In the 48-byte MT21 **ADSI identifiers** section, the fourteen tail spare bytes can be inspected or explicitly edited without changing the terminal's wire identity, dial strings or ADSI identifiers. They are not present in the older 18-byte layout. The 40-byte import remains unchanged because its tail mapping has not been verified.

The later MT31 predial settings for the primary and alternate packet-data access numbers are separate from the manager's dial strings. **Spare fields** exposes the older servicing byte and twelve tail bytes, or the later coin and communication spare flags and five tail bytes, along with the profile's unused predial bits. The named settings and write-only craft values are retained when changing these controls.

Open **Modem parameters** (MT33) to review the modem flags and timers. The older layout has an unsigned spare word where the later layout defines the answer-tone removal delay. Both profiles expose the unassigned general and answer-tone configuration flag bits separately from the named settings. Leave these spare values as imported unless the target's documentation calls for an explicit change.

In MT26's **Display and advertising** section, **Flash degraded-service status messages** controls the service-level prompt independently of called-number display, the calling prompt and advertisement timing. Expand **Spare fields** to inspect the unassigned advertising and prompt-control bits for the verified profiles. On the later layout, changing **Number of languages** edits only the three count bits and preserves the other imported bits and the language order. An imported zero or unrecognised count can remain unchanged until deliberately edited. Select the language options supported by the actual terminal build; the language field alone does not install a language or establish rendering support.

The later **Language scrolling order** panel shows the active leading positions, default language, inactive retained values and the conditional installed prompt-record mapping. Use **Earlier** or **Later** to exchange two active entries without changing the language count or inactive positions. Save the draft using the normal record editor. The panel highlights unsupported active language numbers, repeated languages, and configurations with more than two active languages on the inspected two-language installed runtime. Repetition is an advisory, not a proven rejection.

For the inspected later two-language layout, a single installed language uses MT85. With two distinct languages, the lower language code uses MT85 and the higher uses MT86, regardless of the scrolling order. For example, French can be the default and use MT86 while English uses MT85. Review the corresponding translated prompt records when changing language selections. Ordering does not automatically copy or rewrite them. Imported flag combinations, firmware variants and the terminal's installed state can alter the observed behavior; only matching firmware can establish the actual language and prompt rendering.

Open **Answer supervision** to set the answer delay for a polarity-reversal line and the maximum duration of a wink. For the later 263-byte MT49 profile, a draft can start with a 500 ms answer delay, a 2 second maximum wink and 16 empty number patterns. Use the terminal profile's encoded values when editing line control or the fields attached to a number pattern. The 263-byte layout also exposes two spare bytes per pattern and 32 line-control tail bytes. The older 199-byte import layout does not offer these later controls. Verify supervision on the target line before applying changes to a group.

For a compatible optional **Instant Win** configuration (MT95), edit the disabled or enabled promotion ranges, minimum percentage of card value already used, and three Western display messages. Disabled removes the usage threshold; the other options are 25%, 50% and 75% used. Select a message in **Preview promotion prompt** to see it on the lower 20-cell line. Explicit spare fields preserve the rest of an imported record. The complete later Multi-pay and graphical Multi-pay catalogue profiles do not include MT95. An unprofiled draft can be edited for review, but device support must be established before assignment or publication for another target.

To queue the set for a routine call-in, choose **Prepare now for the next call-in** or **Prepare at a specific time** after previewing the target phones. The date picker uses your browser's local time. The terminal can pick up an available set on its next call-in or explicit table request. Use **Scheduled downloads** on the set or Downloads page to check availability, see the latest attempt, or cancel an open schedule between attempts.

To change when a phone calls in, use **Review routine call-in settings** under its table assignment. Make a draft copy of the assigned set to edit MT35. Set the routine time of day, repeat interval, retry delay and call-record threshold under **Scheduled call-in**. A zero repeat interval means once a day. To apply a one-time clock adjustment, set its date and time and the signed offset in seconds under **Clock adjustment**. Both inputs use the phone's clock. Clear the adjustment date and time to disable it. Publish and deliver the edited set to apply these settings.

For graphical advertising, open **Text and display** and select **Graphical screens 1**, **2**, or **3**. Start from an inactive record or import a completed record for the target firmware. Set and save the screen type before editing its contents. Changing the type replaces that screen's content. A bitmap screen accepts 112 by 72 pixel PNG, BMP, and JPEG artwork. A text screen can store up to 54 lines of 19 cells and shows nine lines at a time in the preview. A mixed screen has four panels with four text lines and six key labels per panel. Configure key destinations and calls in the corresponding key section. Set display and navigation settings in the rotation section of **Graphical screens 1**. The inspected firmware uses that record's header for all 24 screens. Headers from MT132 and MT133 remain editable for exact record maintenance, but do not independently control this rotation.

Open **Spare fields** within the rotation section to inspect or change the three unassigned control bits and header spare byte. Each main screen has two control spare bytes. A bitmap screen has 36 separate unused body bytes outside its artwork, a text screen has 18 outside its stored display cells, and each mixed panel has 23 reserved control bytes. The editor only exposes the body region for the selected known screen type. Changing artwork, text, key actions or timings preserves unrelated spare values; deliberately changing the screen type resets the old body and loads the new editor. The main screen's saved controls and softkeys remain intact.

For each softkey, choose the **Icon ID** from 0 through 63. The two high icon-byte bits appear independently in **Spare fields**. Normal icon selection leaves these bits unchanged; changing them explicitly does not change the selected icon. These reserved values have no assigned display behavior in the verified profile.

To start a new graphical configuration, use **Start graphical advertising from sample artwork** on a draft. It creates MT131, MT132 and MT133 together, with sixteen on-hook globe frames at 500 ms each followed by four original static advertisements at 5 seconds each. The twentieth screen returns to the first. Optionally enable the separate sample off-hook menu at screen 21 to exercise local softkey navigation; it does not dial any numbers. The starter never replaces an existing different record. An exact repeat creates no new revisions. Open the simulator, then edit the saved fields and artwork as needed. Usage collection and connected-call advertising are disabled initially. Select the verified MTR 2.12-based graphical Multi-pay profile for the corresponding type 40 terminal.

For bitmap screens, **Download BMP** exports the artwork shown in the preview as a one-bit Windows bitmap. You can download artwork from a published set or from an unsaved draft. **Invert artwork** swaps lit and unlit pixels. **Clear artwork** blanks the pixels and keeps the screen's links, display settings and spare values. Use **Restore saved artwork** to discard a pending artwork change, or **Save record** to keep it.

Open **Simulate graphical advertising** from any graphical record. Choose **On hook**, **Off hook**, or **Call connected**, then play the configured loop or use the navigation controls when that context enables them. The simulator follows links across all three records and uses each addressed mixed panel's settings and choice keys. It previews choice-key dialing as text. The active record's unsaved changes appear in the simulator. Save a changed screen type to load its new content. Screen dwell uses 10 ms ticks. Off-hook hold and flash intervals use seconds. Browser transitions are a visual preview. Device rendering and timing require a compatible terminal.

Open **Review saved graphical links** to inspect the stored MT131 entry selections, loop links and choice-key destinations across all three records. Filter to the current record or show all references, including resolved links. A finding identifies the source field and target screen or panel. Open the source section directly in the current record to correct a link. Missing companions are distinct from undefined screens in an included record, incompatible or duplicate records, unrecognized addresses, and noncanonical panel bits. MT131 is the runtime rotation reference; MT132 and MT133 header fields are not interpreted as independent rotation starts.

The publication review reports these as advisory findings for the verified graphical profile. Partial sets may intentionally refer to screens already stored on the terminal. The review does not rewrite link bytes, require a complete graphical set, or establish physical navigation behavior. Saved links reflect the last stored revision; use the simulator for unsaved edits.

To collect graphical usage, set **Statistics collection duration (days)** in MT131's rotation section. Zero disables collection. Set a nonzero **Screen owner code** for each screen to include in the report and the **Key owner code** for each softkey you want to identify. For mixed screens, the report uses the main screen's owner and key codes and counts presses across its panels. The terminal reports MT153 after closing a statistics period. See [Uploads](uploads.md) for finding these records and interpreting the counts.

For **Visual prompts**, use the record that matches the terminal build and language slot. Import a complete record to start. Search by message name, ID, wire row or stored text. The editor displays known messages as two rows of up to 20 display cells each. The expanded profile also labels the softkey and calendar rows. You can enter ASCII and supported Western accents. An imported row that uses unmapped glyphs keeps its stored bytes until you edit that row. Keep related prompts consistent across the language records in the set.

For a larger language revision, choose **Visual prompt worksheet**. Filter by wire row, message label or text, or show only changed or unmapped rows. Edit multiple rows, undo individual staged changes, and save the draft once. The worksheet uses stable wire positions and never inserts, deletes or shifts rows. **Export worksheet JSON** includes the current saved and staged text, with null for undecodable rows. To bring in translated text, import a worksheet with the same fixed row count, including one from another compatible language slot. Review the source and destination message types and every proposed row change before staging. Null and omitted rows retain their current text; an explicit empty string clears the selected row. Unmapped text is not converted unless explicitly replaced. The worksheet does not infer hardware-specific glyphs or automatically duplicate edits to another language table.

Under **Terminal features and call setup**, select **Audio-Gram messaging** to edit MT68 for a compatible switch-provided messaging service. Start from an inactive record or import an existing one. Set the access number and protocol version, then review the call and payment permissions, surcharges, signaling, and timers supplied by the service operator. Enter the service key to configure a new record or replace its stored key. Leave the key field blank to keep the stored value. This service requires a compatible terminal build and external messaging switch, not an additional CoinLine NCC endpoint. See [Audio-Gram and Asterisk](audio-gram.md) for a provisioning guide and isolated switch configuration.

The preview shows the enabled service, permitted call and payment types, MT69 statistics collection and service CDR collection separately. The documented terminal uses internal offer-detection thresholds if Busy cycles is below 2 or Unanswered ringing cycles is not greater than Busy cycles. The seventh timing word is labeled **Voice Prompt Play Delay** in the legacy manager; the inspected terminal uses it for line release before reconnecting. The **Reserved fields** section exposes the legacy typed spare words, bytes and flags, without assigning unknown behavior to them. Change reserved values only when their meaning is documented for the target build. Ordinary edits preserve all other bits and bytes.

Under **Reporting and code downloads**, open **Call and carrier statistics settings** to configure MT34. A zero collection interval disables call statistics. Select **Carrier statistics** independently of **Optional CDR mode**. Both Multi-pay profiles support per-carrier statistics; the later profile also supports a combined carrier summary, reported as MT71 reference 253. The optional CDR choices are normal call records only, all call attempts, completed calls only, completed calls excluding local coin, and completed calls excluding local coin and stored-value payments.

In the statistics summary, expand **Spare fields** to inspect its unassigned policy flags. The older profile offers bits 5, 6 and 7, while the later profile offers only bits 6 and 7 because bit 5 has an assigned collection function. Editing a spare does not alter the independent carrier or optional CDR selections.

Set an optional logging start time and duration. This is a window measured from the phone's table-receipt day, not a recurring host-side schedule. A zero optional duration defaults to one day in firmware. During the window, the MT34 optional upload threshold applies; outside it, the normal MT35 call-record threshold applies. A zero threshold disables count-triggered call-ins, not routine scheduled calls. For summary collection and MT32 communications statistics, enter report timestamps sequentially after the start time, with unused slots last. When the first timestamp follows the start, the terminal uses daily checkpoints instead of a multi-day interval. The preview explains this distinction. The downstream Uploads page labels the later combined carrier report separately from individual carrier references.

In **Communications statistics settings** (MT32), expand **Performance histogram bucket ranges (MT37)** to review the configured start and interval in seconds for all four measurement categories. Bucket 1 is below the start, buckets 2 through 6 each contain one interval, and bucket 7 contains the remaining times. An exact upper boundary belongs to the next bucket; a zero interval leaves five middle buckets empty. Changes to the existing MT32 fields update this preview before saving. If the calculated final boundary exceeds the terminal's 16-bit limit of 655.35 seconds, the preview instead flags a wrap. An imported negative or unavailable value is also shown for review without replacing it. These ranges describe the selected configuration, not the counts from a historical upload. Do not interpret a previous MT37 using the phone's current table unless its reporting-period configuration has been established.

The set summary shows the operating type, enabled coin slots and configured magnetic-card ranges for the recognized profiles. Review any provisioning findings before assigning the set.

Under **Cards, coin and carriers**, open **Coin validation** (MT50) to edit the 16 validator slots. A new 105-byte record starts with all windows and coin acceptance disabled, with zero placeholder values and capacities. It is not a calibrated coin profile. Enter the values and volumes for the installed validator and the cash-box and escrow capacities and thresholds before using it on a phone. The slot's **Enable validator window** and **Accept coin** settings are independent of the six unnamed flag bits under **Spare fields**. The cash-box section also has eight reserved bytes. Ordinary coin settings retain those values.

Open the card acceptance record for the target firmware. You can start a blank card record on a draft. Select a range, set its six-digit limits and choose its card standard. Save the standard to load the matching sections. For magnetic cards, add service codes in order and use **Accept listed service codes only** to decide whether the list allows or rejects those codes. An empty list leaves service-code filtering disabled. The later profile also exposes data-spill steps for magnetic cards and discount, balance and reload settings for stored-value cards. Changing card families clears the shared record data for that range.

For a compatible stored-value standard, use the issuer and value sections to select validation key slots, unit limits and manufacturer codes. In the later card profile, an enabled odd value code requires unit index 0 on the preceding even code. The **Smart-card parameters** record supplies the unit limits and encoded validation slots. The older MT93 profile also exposes large-value limits and toll rebates. The later profile lets you choose a charge adjustment, percentage multiplier or replacement tariff for each call zone. Save a changed discount method before entering its values in the browser. Use an encoded replacement key supplied for that firmware slot. Leave the field blank to retain the stored bytes. The later profile's **Discount rate reserved configuration** section exposes six separate reserved bytes, and **Reserved configuration** exposes the 34 trailing bytes. The older profile has 30 trailing reserved bytes. None of these fields reveals or edits the stored validation slots.

Open **Spare table and e-purse** for the later MT72 profile. **Settings** provides collection, transport, settlement, reload and alternate operator fields. **Byte grid** shows the full 1,000-byte payload in pages. On a draft, type two hexadecimal digits over a byte or paste a sequence starting at the selected offset. Use the page selector, arrow keys or Page Up and Page Down to move through the record. Home and End move within a row. Add Ctrl or Command to jump to the start or end of the record. Protected bytes are masked in the grid. Replace them through the write-only settings for their fields. The message type remains fixed. You can save settings and byte edits together when their offsets do not overlap.

For compatible firmware, open **Remote code download settings** under **Reporting and code downloads**. Set the terminal start time in UTC, the code server number and speed, the requested ROM and application revisions, and the retry settings. Enter the server-supplied authentication value in the write-only field. The code block groups cover all 256 4 KiB blocks in the request bitmap. Start with a blank draft or import the parameters for the target build. In **Reserved code-download bytes**, open **Spare fields** to inspect the 26 tail bytes independently. The authentication value remains write-only. Ordinary schedule changes, allocation and cancellation retain the reserved values.

Publish a set containing only MT94 to open **Schedule firmware parameters**. Choose the phones and when the record becomes available for pickup. The terminal start time is a separate setting and must be later than pickup availability. A routine call-in or callback delivers the parameters. The phone’s normal data assignment is independent of this schedule. Use scheduled download history to cancel a pending delivery. For the latest delivered enabled firmware schedule, choose **Queue firmware cancellation**. CoinLine prepares a separate MT94 with its enable flag cleared and links to the cancellation batch. The disabled record must reach the phone and receive its acknowledgement on a subsequent call-in. A delivered cancellation cannot undo an upgrade that has already occurred.

Choose **Terminal ID range** to select phones by their ten-digit wire IDs. Both endpoints are included. Enter one ID and leave the last ID blank for a single phone. Enter a digit prefix followed by `*` to fill the range through all suffixes. Choose **Current software version** to select phones whose latest complete NCC software report matches both controller version fields exactly. Find those values in **Terminal Status**. CoinLine checks the eligible phones again when you confirm the schedule.

By default, the firmware scheduler keeps each phone's existing pending or delivered firmware schedule. Select **Allow rescheduling existing firmware parameters** before previewing to include those phones. The preview shows how many schedules will be replaced and which phones will be skipped. A pending ordinary data download or an active firmware transfer makes a phone ineligible. Confirmation cancels any replaced pending batch and creates a separate new batch. Previously delivered records remain in the history. The new parameters require their own acknowledgement.

For an enabled MT94 with selected code blocks, choose **Allocate terminal starts across a daily download window**. Enter the first date, daily UTC start and end, available server count and estimated minutes per phone. A time range ending before its start continues into the following day. The raw 8N1 transfer estimate uses the number of selected 4 KiB blocks and modem speed as a lower bound. Allow additional time for connection setup, protocol overhead and retries. The preview allocates complete slots in wire-terminal-ID order using the declared capacity of the code-server number. It accounts for existing window reservations from other jobs using the same encoded dial route, including partial overlaps. Additional phones roll into the next daily window. Confirm the preview to prepare immutable MT94 copies containing their individual start dates. The published source remains unchanged. The source set's schedule history links to the allocated records and shows their terminal starts separately from parameter preparation and acknowledgement.

A pending reservation is released when its schedule is cancelled or replaced. An acknowledged reservation remains until its slot ends or the phone acknowledges superseding firmware parameters. The preview identifies fixed-time schedules starting on or after the first selected window that lack a reserved duration. Actual retries can extend beyond a planned slot, and different dial numbers are treated as separate pools even if they reach the same service.

On a phone’s detail page, use **Special callback** to ask it to call back after its next management contact. Choose **As soon as possible** or enter a time in your browser’s time zone. The clock offset describes the phone’s clock relative to UTC. Leave it at zero for a phone synchronized to UTC. Select **Deliver assigned tables on callback** to deliver the phone’s current published assignment when it calls back. A due scheduled set takes priority. Refresh the panel to see when the phone acknowledged the request and returned. A phone that already acknowledged a cancelled request may still call.

Use **Terminal inventory** on the phone’s detail page to record the installation location details, route and stop, administrative codes, equipment quantities and costs. The registered location and customer appear above those fields. The phone supplies its hardware serial in an NCC status report. On **Phones**, filter by name, terminal ID, region code or terminal family.

**Terminal identity history** shows the previous NCC ID and terminal type with the dates they were changed in CoinLine. Use **Edit terminal ID** to change the ID the Manager matches. Set the same ID on the phone, then use **Refresh history** after its next NCC call to see when CoinLine first matched the new ID. If the phone's assigned configuration includes its old ID in MT21, assign a revised set with the new ID before scheduling the access record.

On phone detail, **Cashbox** shows the latest reported balance for each box and the collection history. The collection total reflects the terminal's report, which can combine multiple removals. **Last rate** shows the host quote. **Uploads** shows the terminal's call detail and reported coin amount.

In the matching **Carrier screens** record, select the carrier and check which card ranges it accepts. A new draft carrier record starts with no assigned carriers. Match the carrier reference identifier, not the row position. Give distinct carriers distinct identifiers: when two rows have the same reference, the phone uses the first. **Accept coins and stored-value cards** controls cash payment for that carrier. Feature Group B requires a call-screening row number. The later carrier record also exposes terminal-rate permissions by call zone and payment type. **Provisioning review** shows missing primary and payment carrier references, conflicting duplicate identifiers, card ranges that their selected carrier would reject, and configured coin carriers that have coin acceptance turned off. These findings link directly to the affected editor and are advisory. Reference 255 selects no carrier; zero may select the local exchange without a carrier row.

In a native MT23 or MT135 carrier record, **Carrier selection** contains the table's trailing spare bytes. Each carrier row has its own **Spare fields**. The older layout has an unused high nibble of its card bitmap and a separate row spare byte. The later layout has two unused terminal-rate acceptance bits. Both layouts have unassigned carrier control bits. These settings are separate from accepted card positions, carrier branding, screening and ordinary rate controls.

The **Carrier library** in Setup holds reusable definitions by carrier ID (up to six characters) and wire profile. Create a definition from the native fields, or select a saved carrier row in a table set and use **Save this row to library**. To apply a library entry, select the destination row in a draft MT23 or MT135, choose the matching definition, decide whether to keep or clear that row's accepted card ranges, and choose the target MT92 access entry if Feature Group B is enabled. Card bitmaps and screening indexes depend on the destination set; they are not copied silently from a different configuration. The library editor also has a collapsed **Spare fields** section for its named row. Under **Reserved fields for this row**, the default is **Keep destination reserved fields**. Choose **Copy definition reserved fields** only when the destination requires those exact reserved settings. This choice applies to the row, not the record-wide tail, and does not change the separate card acceptance choice. Applying a definition creates a revision-checked snapshot with an audit event. Later library edits or deletion do not change existing table sets.

In the draft MT22 or MT134 card editor, use **Card sequence** to move an existing configured range to a blank position. The older profile has 20 positions, the later profile has 32. Save other field edits before moving. The matching MT23 or MT135 carrier record must be present because carrier acceptance is indexed by the card position. CoinLine moves the complete card row, preserves the imported blank row's bytes, and swaps just the two position bits in every carrier row. Both changes are saved together; a stale card or carrier revision prevents the move. Published sets remain read-only. When ready, publish the revised set and download both the card and matching carrier records together. The operation does not change a live phone by itself.

**Card Master List** in Setup contains reusable named card acceptance definitions, distinct from card accounts or payment processing. Enter a card type ID of up to four characters and an optional descriptive name. Choose the MT22 or MT134 profile. The corresponding card-standard detail sections include the identified magnetic, service-code and stored-value settings. A definition belongs to one wire profile; use a separate definition for another layout.

Known card standards expose their profile-specific reserved fields in both the native editor and Card Master List. Older MT22 standard 10 includes a stored-value spare byte. Later MT134 configured standards include three additional-control spare bits; magnetic standards also have four unassigned spill-terminator bits. Later stored-value discounts remain named settings, not spares. These controls retain surrounding imported values, do not alter validation policy, and are hidden for unidentified formats. A master definition includes the complete card row, so adding or refreshing a linked definition also copies its row's reserved values. Review those values before applying a definition captured from another configuration.

In the draft card editor, use **Card configuration membership** to add a definition to the first blank position. Review the destination-specific references, including the selected carrier and its accepted positions, and any applicable reload, discount, validation-slot and unit-table references. These are settings and indexes, not cardholder details or validation keys. CoinLine does not assume that another set's reference numbers mean the same thing. Verify the referenced MT92 and MT93 data on the destination before enabling those services. The selected card configuration and changes to matching carrier acceptance are saved together. The complete legacy 20- or 32-position capacity is available.

You can capture a configured row using **Save position to Master List** and then **Link matching existing position** if its reusable fields and current target references exactly match. This attaches host-level provenance without changing terminal bytes. **Refresh linked card** applies the latest master revision in a draft using the existing target mappings, or lets you explicitly choose new mappings. Direct edits to a linked card row detach that position from the master definition; other rows keep their links. A move carries the link with the row. Removing an entry replaces only its selected card position with an empty template and clears its corresponding acceptance bits; the Master List definition remains. Copying or cloning a record also retains the saved definition identity and applied revision.

Editing a master definition does not rewrite saved configurations. **Where this definition is used** lists linked configurations, positions, applied revisions, and counts of assigned phones. Archive a definition to remove it from the active master list without changing historical snapshots. Archived definitions can be restored, but cannot be added or distributed while archived.

To distribute a saved revision to affected phones, select **Preview affected phones**. The preview reports configuration positions, phone counts, selected records, metadata-only updates, and skipped reasons. Changed card families or issuer identities require explicit mapping review in a draft instead of an automatic rollout. Phones with open downloads, inactive phones, and incompatible registered targets are skipped. On confirmation, CoinLine creates new immutable published snapshots and updates the eligible phones' desired assignments, preserving their previous sets for rollback. It immediately prepares selected-card download batches only where bytes changed; declared record dependencies are included. A metadata-only change prepares no terminal download. The prepared batch is not a device acknowledgement. Monitor **Downloads** after the next NCC call-in to confirm each phone's result. No unrelated configuration family is repacked merely because the master definition changed.

The carrier **Display name** is the 20-cell lower line of the terminal's branding display. For the standard local-provider prompt, review carrier row 0 and the carrier assigned reference 0; select **Show the carrier's display name** where appropriate. The preview uses a typical introductory line, while the actual language-specific introductory text is configured in MT27/28 or MT85/86. Changing the name does not require changing advertising, carrier access digits or rates.

In **Dialing, screening and service**, open the numbering plan and select **Numbering rules**. Choose **Dialing** to configure matching, fallback, prefix conversion and call classifications. Choose **Display formatting** to configure digit groups and separators. Each rule set starts at Rule 1. After adding or removing rules, check the links from the start rule before saving. A draft save validates links and available space, and shows an error if the edit would overwrite unrecognized record data.

Select the firmware profile before editing an untargeted MT62 import. The older profile has 180 dialing-rule bytes, 132 display-formatting bytes, and a separate eight-byte custom currency format. The verified later standard and graphical Multi-pay profiles have 180 dialing-rule bytes and 140 display-formatting bytes; they do not offer the older currency controls. The rule editor displays the capacity of the selected profile and warns about exceeding it. Editing a rule without changing its size preserves the original links and unused gaps. **Spare fields** contains the verified unused termination and dialing-search bits and the profile-specific unused header bytes. The older currency flags have independent spares. The later layout does not expose the older answer-supervision timer or the international-build manager timeout.

Under **Settings**, select **Number display and currency** to change the symbol, spoken currency and number of decimal places. The same record also holds digit timers, carrier behavior and the call classifications assigned after a rate response.

In **Dialing, screening and service**, open **Quick Access Keys**. Select the five-key or ten-key panel and choose a key. The five-key view shows slots 6 through 10. The panel selection controls the editor view, and the saved MT55 retains all ten slots. Enter the destination, customer reference and display lines for the key. An information key can display text with an empty destination. Paid destinations use an MT73 rate index. For free Feature Group B access, the same field selects the carrier reference. Call-screening rules use the same distinction. On the two documented Multi-pay profiles, **Firmware compatibility** warns about missing carrier identifiers in MT23 or MT135, or reliance on the installed carrier record when it is not included in the set. Use the carrier-prefix option when the caller should complete the number after selecting the key. [Repertory dialer reference](https://github.com/hharte/mm_manager/blob/main/src/mm_rdlist.c)

**Quick Access Customers** in Setup is a separate directory for key customers, not the fleet Customers screen. Create a unique, nonzero six-digit customer reference and enter its name. Optional fields include billing comments, contact name, telephone, street, city, province or state, postal or ZIP code, and notes. Search by reference or name; use the ordered previous and next customer controls or browse pages. Customer references are immutable, so an archived reference cannot accidentally be assigned to another customer. An archived entry can be restored.

In a draft MT55 record, choose a key and select **Look up customer**. Search the directory, then choose **Use** beside the desired reference. This stages only the numeric reference field; select **Save record** to write it to the draft. **Clear customer reference** stages zero without clearing the other key settings. Imported references outside the six-digit directory remain intact unless explicitly edited. Only the reference is encoded in the terminal record. The customer's name, contact information and billing notes stay on the host and are not added to the download. The **Quick Access Key customer reference lookup** permission grants the minimal lookup results without access to the directory's contact and billing details. Stock-firmware billing behavior for customer references still requires device acceptance.

Use **Clear key** to stage a blank key, then use **Save record** to write the draft. **Undo clear** restores the staged edits for that key before saving. Clearing removes the destination, display text, customer reference and supported key options while preserving unassigned bits and the other slots. Choose the firmware layout before editing model-specific key options.

Both Quick Access Key display lines support the verified Western display glyphs, including French and Spanish accents. Unmapped imported text is retained until that line is explicitly changed. The older profile offers **Audio-Gram message key** for compatible messaging-enabled firmware. The later profile has its own PDS, target CDR and configurable-access settings. Each profile exposes its identified unnamed spare flags in a collapsed **Spare fields** section. Clear resets the older message-key flag as well as the advertising flag; other unassigned flags remain intact.

In the expanded **Call screening** layouts, number patterns accept `*` and `#`. Choose **Unlimited** to match any number of additional digits after the pattern. On the verified 200-entry Multi-pay profile, a standard free rule needs rate index `255`. A standard paid rule that uses a tariff directly needs an MT73 index from `0` through `127`. The firmware review highlights the relevant screening row before publishing. When the set refers to a tariff but omits MT73, review the warning and confirm the phone already has the expected tariffs for a partial update.

Use `?` in a pattern to match one digit at that position. The compact MT24 and MT59 layouts accept decimal digits and the `B` screening link marker. For an imported MT59, choose the layout used by the target firmware. Both MT59 variants are 1,021 bytes. The compact layout has 85 slots of 12 bytes, and the expanded layout has 60 slots of 17 bytes. CoinLine remembers the choice after the first change is saved. Reimport the record to choose another layout. The 60-slot editors open on the first 50 entries for the legacy workflow. Select **All 60 wire slots** to see the full record. The 85-slot, 180-slot and 200-slot editors show their full capacities. [Call-screening record reference](https://github.com/hharte/mm_manager/blob/main/src/mm_callscrn.c)

**Blank entry** clears the number and description, plus the trailing wildcard count on expanded layouts. **Delete entry** also resets the supported settings. Both retain the slot number and preserve unassigned bits. This keeps later slot numbers and their references stable. Check for other records that depend on the cleared slot before publishing. Descriptions stay with the table version in CoinLine.

In the later 180-slot MT92 editor, **Set speed dial** accepts an asterisk followed by one or two digits and a full destination. For manual dialing, keep a regular rule for that destination with matching call settings. The editor also encodes N11 service codes as translated screening entries for compatible routing. Save, publish and download the record, then verify the shortcut on the target phone.

The later 180-slot MT92 layout also has **Enable PDS dialing** on each rule. This is a normal assigned field, not a spare. **Blank entry** preserves that setting; **Delete entry** clears it with the other assigned settings. In the verified 180- and 200-slot MT92 layouts, **Spare fields** exposes the unassigned secondary identifier values and three trailing bytes. The ambiguous or unconfirmed compact and expanded MT59 layouts do not offer these profile-specific new controls.

Leave **Restrict route to coin payment** off for a Multi-pay route that should also accept cards. A phone can show **Selected carrier not supported by card** for a matching coin-only screening rule, even when the card passes its carrier's acceptance list. Review the screening rule and the carrier's accepted card ranges when you see this message.

Open **Service Level Restrictions** to set MT58. Both documented Multi-pay layouts support unrestricted service, free and emergency calls only, disabling coin and smart-card calls, and restricting in-call keypad signaling in coin or smart-card operating mode. The latter is how the firmware implements level 3; the legacy desktop help describes it more broadly. The later layout also supports configurable restricted access (level 4). It allows complete screening matches or quick-access calls that carry the corresponding **Allow in configurable restricted service** flag. Review those permitted routes explicitly before applying this restriction; a partial download may rely on the screening and key records already installed on the phone.

MT58's **Spare fields** section exposes the 20 reserved unsigned bytes. Their semantics are not assigned in the verified firmware layouts. Ordinary schedule edits retain all of them. Read-only operators can inspect the values; changing them requires normal table-record Update permission.

Set a start time on the phone's local clock and a positive duration. The preview shows the end time, including overnight rollover. The restriction recurs daily, activates with the handset on hook and cover closed, and is suspended when the cover is opened. A 24-hour duration is capped by the firmware at 23 hours, 59 minutes and 59 seconds. The editor preserves the record's reserved bytes. Verify the intended dialing behavior and expiry on the target phone before a wider rollout.

Under **Rates and local dialing**, use **Rate table** to edit the phone's MT73 charge and duration steps. A new template starts with all 128 rates marked unavailable. Choose the profile for the installed firmware. The later profile exposes international toll and local data-port rate classes. Choose the rate classification, enter the charges in cents, and use **Unlimited initial period** or **Unlimited additional period** when that charge applies for the rest of the call. The terminal can also obtain a charge from CoinLine when the route and rate classification call for host rating.

For compatible firmware, **NPA set-based rating** sets a fallback by area code. **International set-based rating** sets rates by destination prefix and the action when no prefix matches. The rate pickers show the corresponding MT73 row numbers. Enable the matching set-based rating switches in the later MT26 feature record. Deliver the matching records together, or confirm the phone already has the referenced tariffs.

Under **Rates and local dialing**, choose the local-dialing segment for the phone's table format. Start with a blank segment or import a complete record. Enter its three-digit area code, then use **Find entry** to locate the exchanges you want to rate. Uncompressed segments can reference MT73 rows 0 through 127. Compressed segments can use rows 0 through 15, and double-compressed segments can use rows 0 through 3. Clearing the area code disables lookups in that segment while retaining its exchange values.

Open **Import or export exchange rates** to import a UTF-8 spreadsheet with `NPA,NXX,RateIndex` columns, an extracted NANPA utilized-code text report, or an extracted CNA code-status CSV. The file can contain several area codes and remains available while you switch records in the table set. Choose the area code for the open segment. For public reports, choose which rate centers use the selected index and enter the index for other in-service exchanges. Assignment data identifies the exchanges and their centers. Set the indexes according to your tariff. [NANPA utilized-code reports](https://nanpa.com/reports/co-code-reports/cocodes_assign) · [CNA code status](https://www.cnac.ca/co_codes/co_code_status.htm)

To generate indices from the phone's home exchange, use an in-service U.S. routing crosswalk with `NPA,NXX,LATA` columns. For Canada, load the extracted CNA code-status CSV with its **Province** column, then load the **CNA Exchange Area Listing** CSV. CoinLine joins each in-service code to the LIR for its province, NPA and exchange area. A prepared `NPA,NXX,LIR` crosswalk also works. Both crosswalk formats support a combined `NPA-NXX` column. Files are read in the browser. [NANPA assignment report fields](https://nanpa.com/reports/co-code-reports/cocodes_assign) · [CNA Exchange Area Listing](https://cnac.ca/reference_data/canadian_exchange_area_listing.htm)

Enter the phone's home NPA-NXX. Select the destination NPA for the open record, and choose the rate indices for exchanges in the same LATA or LIR, exchanges in other regions and unmapped exchanges as applicable. Review the counts before staging. Regional membership groups the exchanges and the phone's tariff determines which calls qualify for local rates. Repeat on the appropriate segment for each destination NPA. [FCC example of expanded local calling across LATA boundaries](https://docs.fcc.gov/public/attachments/DA-07-2465A1.pdf)

Choose **Preview import** to review changed exchanges. With the same area code, leave the unlisted index blank to retain values for exchanges the file did not supply. Changing the area code requires an explicit index for unlisted exchanges. **Stage import** adds the previewed changes to the editor. **Save record** writes the changes to the draft using its current revision. **Download rate-index CSV** exports the open segment's 800 exchange values.

For offline exchange rating on MTR 1.9 Multi-pay, include the compressed dialing segment and its MT73 tariff rows. Make sure the numbering plan identifies the exchange for rating. A matching paid call-screening rule can select its own tariff and bypass the exchange lookup. After delivery, check the record acknowledgements and dial a test destination to verify the phone's quote.

If a card range selects a carrier, open that carrier in **Cards, coin and carriers** and enable **Accept card range** for the corresponding range number. For Multi-pay service, also enable **Accept coins and stored-value cards** on the carrier used for coin calls. When publishing a partial update, confirm the matching card and carrier records are already on the phone. An inter-area call can pass the card format check and still be rejected by the phone's carrier acceptance list before it requests authorization from CoinLine.

The MT73 tariff editor exposes the 32 reserved header bytes under **Tariff effective date** in both verified profiles. Changing the tariff owner or a rate row leaves those bytes unchanged. In **International set-based rating** (MT151), the no-match selector and default rate are separate from the six unnamed fallback bits and one reserved byte under **Spare fields**.

The **Set-based rating preview** in MT150 accepts a three-digit area code and identifies its packed entry and referenced MT73 rate, external-rating candidate or rejection. For MT151, enter destination digits after the international access prefix. The preview checks the first five digits, trying longer numeric prefixes before shorter ones, and uses the first matching entry when a prefix occurs more than once. It also identifies no-match and imported high-code fallback paths. A matched destination using a fallback code of 100 or greater can select MT73 row 28 or 29 when the configured default code is 0 or 1; ordinary no-match lookups interpret those default codes directly. Review this combination rather than assume the two paths are equivalent.

Use **Open selected entry** to jump to the relevant section even when the editor is filtered, and **Open fallback settings** to review a selected fallback. The preview reflects staged field changes and does not save or queue a record. It does not look up host rates, calculate charges, establish call acceptance or confirm terminal behavior. Earlier dialing and screening rules, local dialing tables, feature settings and the actual MT73 rate can all affect the result.

For compatible firmware, edit the ten **Discount rate** entries in the later **Smart-card parameters** record (MT93). Each entry can apply a different amount, percentage or replacement tariff per call zone. Then open **Holiday and time-of-day discounts** (MT152). Choose the weekday, Saturday, Sunday or holiday period and set its start and end time. Select the payment types and the matching MT93 entry for each call zone. Use 00:00 to 24:00 for an all-day period. Equal start and end times leave the period inactive. An end before the start matches times on either side of midnight within the selected day's schedule. The first matching period takes precedence. A holiday uses its own schedule in place of the usual day of the week. The provisioning review flags active schedules that rely on the phone's existing MT93 discounts. For each period, the two unassigned bits of each call-zone setting appear separately from the payment selector and discount index. The **Reserved configuration** section exposes the ten trailing bytes. Leave these fields unchanged unless required by a documented firmware use.

Use the **Time-of-day and holiday schedule preview** to choose an example date, local phone time, call zone and payment. It displays the recurring holiday match or ordinary day category, both configured intervals, the first matching period, the selected MT93 reference and the corresponding payment mask. Start times are inclusive and end times are exclusive. When intervals overlap, period 1 wins even if its payment option is disabled for the selected example; period 2 is not a fallback. The provisioning review also reports overlapping or invalid stored times without rewriting them. The preview includes unsaved edits, makes no quote, and does not establish the terminal's clock, loaded MT93 record or actual billing behavior.

In **Phones**, open a phone and expand **Phone groups** to choose its memberships. A phone can belong to up to 40 groups. Its primary group appears in the phone list. Every saved membership is included in that group's assignment preview. To reuse another phone's memberships, find the source phone, choose **Review copied groups**, and save the resulting selection. The current selections stay in place, and groups outside the phone's customer scope are reported as unavailable.

From **Phone groups**, choose **Manage** on a group to see its members. Clear **Show members only** to find eligible phones and add them. Choose **Review copied phones** to add members of a source group to the selection. Phones that have reached their group limit or belong to a different customer are reported as unavailable. Review the checked memberships before saving. The copy keeps the destination group's current members. Removing a phone's primary membership promotes one of its remaining memberships if available.

Select **Terminal family** when adding or editing a phone. The picker lists the legacy Maximizer family names and type numbers. The **Phones** list can filter by family, and assignment previews show the family of each phone. Use **Installed firmware** to record the precise build and **Terminal operating mode** in the set's MT26 editor to choose card-only, Multi-pay or coin-only operation.

Open **Terminal family checklist** in a table set to compare its saved records with the legacy mandatory and feature-specific tables for a family. From an assigned phone, use **Review table requirements for this family** to open the same view preselected. Inspect missing groups, known target lengths, recognized editor layouts and packed screening capacities. Open a present record directly from the checklist. It describes a full installation, and a partial download can rely on existing terminal data. Confirm the exact installed firmware and device behavior before treating the listed candidates as compatible.

Open **Terminal status** to filter decoded alarms, maintenance reports, status flags and software versions by phone or report type. An upload or table request can include status and version records in the same message. The console shows each report separately. The version report includes the operating mode stored in the phone.

Open an alarm to see its name and number, the phone that reported it, and when CoinLine recorded it. The phone's own timestamp appears separately when the record contains a valid clock. ## Configurable service restrictions

On the later packed profile, select configurable restricted access in MT58 to review saved permitted entries in the included MT92 Call-Screening List and MT55 Quick Access Keys. The review shows exact entry/key positions, decoded destination or pattern, wildcard/translation markers, classification, free flags and marked-but-blank, denied, information-only or unmapped entries. On the verified graphical profile, it additionally lists marked MT131/132/133 choice keys. The terminal uses panel-specific button settings for mixed screens and main-screen button settings for bitmap and text screens, so mixed-screen stored defaults are not counted as callable routes. The legacy graphical-terminal guidance specifies free restricted routes; a marked paid route is shown as a candidate with a separate payment-behavior warning, not as proven allowed. Missing companions in a partial set are explicitly unknown; the terminal may retain an existing record. Unverified profiles are not decoded as if their lengths established field meanings.

This is a read-only review of stored companion bytes, independent of the daily schedule edit. It does not change the markings in MT55 or MT92, or establish actual authorization, rating, connection or device restriction behavior. Change the marking in the appropriate native editor and reopen MT58 to review the saved companion record.

## Inmate Feature Configurations

From **Table sets**, open **Inmate Feature Configurations**. The editor covers PIN entry, call processing, voice announcements, disconnect warnings, recording equipment, call timers and other settings. Enter a name of up to six characters and an optional description. Use **Copy as new** to reuse the current settings under a new name.

The editor checks the legacy timer ranges and the minimum 10-second gap between disconnect warnings. Recorder codes accept up to two DTMF characters, and the automated operator code accepts up to three. A saved configuration can be selected in the [phone's Inmate terminal configuration panel](terminals.md#inmate-terminal-configuration). Terminal download awaits evidence of the Inmate firmware record layout.


## Reference record catalogue

Open **Table definitions** to find the master record catalogue. Search by MT number, reference name or registered definition name, and filter by native editor, observed length, documented reference, scheduler record or operational message. Expand a record to inspect exact packed layout lengths and template availability separately from firmware-specific lengths and retained emulator MT14 observations. A narrow behavior observation is displayed only where a previous emulator milestone established it; it does not certify all fields or physical hardware.

The registered definitions remain a separate storage directory. A historical stored name is not authoritative wire semantics; for example MT10 is terminal status and MT20 is clock synchronization. MT94 is a separate code-download scheduling record. Viewing the reference catalogue does not change definitions, sets, assignments or payload hashes.
